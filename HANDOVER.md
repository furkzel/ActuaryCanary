# Handover

Read this file first. It is the only status document. Everything else is code, specifications (`spec/`), decision records (`docs/decisions/`) or the blueprint (`docs/blueprint.md`).

## What this is
ActuaryCanary turns insurance data in any layout into an auditable, early-warning actuarial report on your own computer. Analytics-first actuarial data science platform; see `docs/blueprint.md` sections 1 and 2.

## How to work here
- Setup `just setup` · Check `just check` (format, lint, types, fast tests under 30 s) · All tests `just test-all` · Run `canary run <folder>` or `canary demo` · Documentation `just docs-check`, `just notes`, `just examples` · Windows program `just package`
- Specification first: change `spec/` before code. One rule, one spec file. Tests name the spec ID they prove.
- Decisions: one short numbered record per choice in `docs/decisions/`; records are superseded, never edited (owner-approved exceptions: 0017, 0023). Take the next free number after looking at the folder, not at this file.
- One branch per work item, `s/<ID>-<slug>`; the owner merges to `main`.
- No per-work-item report files. Detail goes into commit messages; status goes here.
- Commit messages carry no attribution trailers and no generated-by lines, whatever the default of the tool.

## Map
- `src/actuarycanary/<component>/` — one subpackage per blueprint component: io, recognition, canonical, quality, convert, structures, measures, methods, modules, report, manifest (also project metadata), spec, cli
- `spec/` — specifications, one subfolder per kind: data, conventions, measures, methods, modules, aliases
- `tests/` — mirrors the package; `conftest.py` sets Hypothesis profiles and holds the shared runs of the fast suite (`default_run`, `cli_run`); a test that needs a run of its own is marked `slow`
- `tests/benchmarks/` — frozen reference values (`raa`, `genins`, `clrd_wkcomp`) and `load.py`; `tests/fixtures/hand/` — hand-worked 4×4 fixtures
- `synthetic/scenarios/*.yaml` — synthetic scenario parameters (`baseline.yaml` is the base); code in `src/actuarycanary/synthetic/`
- `docs/` — `blueprint.md`, `guide.md` (user guide), `methods/` (eleven method notes with generated worked examples), `tools/` (their generators), `decisions/` records 0001–0045, 0050–0064, 0070–0075, 0080–0084, 0090–0091, 0100–0102, 0110, 0120, 0130, 0150, 0200–0212, 0220–0225 and 0600–0606 (the other numbers of each block are unused on purpose: the number blocks of the items; the next free number is 0151, 0213, 0226 or 0607 by block, after looking at the folder)
- `examples/` — `demo` (ten accident years, what `canary demo` runs), `baseline` and `messy_headers` (four years, for tests), each with its `report/`; `packaging/` — PyInstaller specification, entry point, manifest comparison; `README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `LICENSE` (MIT)
- `project.yaml` — project metadata, single source for CLI and report
- `.github/workflows/ci.yml` — `just check` on Ubuntu and Windows · `.github/workflows/release.yml` — Windows program and release archive on a `v*` tag (ran green for `v0.1.0-rc1` and `v0.1.0-rc2`; the tag must equal the version, 1.0.0)
