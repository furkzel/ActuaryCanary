# 0101 — The documentation check and the method notes

## Context
P12 asks for one user guide, one note per tier A method with a worked example whose numbers come from the hand fixtures through a script, and a docs check in `just check` that resolves every link and every spec ID without a network.

## Decision
- **Docs check.** `tests/docs/test_docs.py`, in the fast suite, so `just check` runs it without a change to the `check` recipe; `just docs-check` runs it alone. It checks, offline: every relative link and image of `README.md`, `CONTRIBUTING.md`, `CHANGELOG.md` and every `docs/**/*.md` points at an existing file and, for a Markdown target, an existing heading (anchors as GitHub makes them); links with a scheme (`http`, `mailto`) are not followed. Every spec ID named in the README, CONTRIBUTING, CHANGELOG, the guide and the method notes exists in `spec/` (measures, methods, modules, conventions, aliases, report rules and the `DV-` rules of the data specifications). Decision records and the blueprint are not scanned for IDs: they describe history and plans and may name IDs that were never built. Fenced code is ignored.
- **Method notes.** `docs/methods/<spec>.md`, one per method specification MT01 to MT10, plus `RT01-loss-and-combined-ratios.md` for the profitability method of the blueprint's tier A table (loss, expense and combined ratios), which is built from measures and has no `MT` specification. The descriptive profiling measures get no note: they are measures with their own specifications. Each note has purpose, theory with formulas, assumptions and how to check them, what the platform does, a worked example and references.
- **Worked examples are generated.** `docs/tools/worked_examples.py` calls the platform's own code and rewrites the block between two marker comments in each note (`just notes`); the docs test fails when a note differs from what the code gives today. Sources: the 4 x 4 hand fixtures (MT02 to MT05, MT10, the ratios), the three-claim fixture of the MT01 test, the GenIns benchmark triangle for MT06 (the 4 x 4 triangle has too few columns for the Mack variance estimate), the fixtures of the MT08 and MT09 tests. Two examples add an assumption and say so: MT07 restates the hand paid triangle with an assumed index growing 20 per cent a year, one payment date per year (the platform uses the month); the ratios example assumes an expense and a commission ratio. MT09 uses 50 trees instead of the default 200 to keep each docs test under 0.5 s, and says so in the note.
- **Prose numbers.** Numbers in the prose of a note are specification defaults (0.5, 3.5, 100 claims); every number derived from data is in a generated block.

## Consequences
- A change to a method or a fixture that moves a number fails the docs test until `just notes` is run and the diff read.
- The benchmark file of GenIns records that no published source was opened: the standard errors in the MT06 example are those of the chainladder package, which the tests match to 1e-6, not figures read from Mack (1993).
- References are those of the specifications; the notes add Taylor and Ashe (the origin of GenIns) and England and Verrall, whose bibliographic details are UNVERIFIED against the originals.
