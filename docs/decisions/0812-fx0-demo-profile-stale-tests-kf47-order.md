# 0812 — Fx0: the demo's profile, two stale tests, a stated order for KF47

## Context
Release 1.3.0 is prepared and not tagged; the criteria table of the gate lists three failing slow tests (row 5) and a demo that does not equal `canary run` (row 6). The number 0812 is the next free one after 0811. No workflow summary was handed to this item, so only the listed failures are in scope. The last-digit difference of row 6 has its own record (0813).

## Decisions
- **The version stays 1.3.0.** The tag is not set, so these fixes are part of 1.3.0: no version string, changelog heading or golden run id moves.
- **The demo runs on its shipped confirmed profile.** `place_demo_profiles` (`cli/demo.py`) copies the ledger account-mapping profiles that lie beside the committed report (`examples/demo/report/ledger-<fingerprint>.yaml`, record 0811) byte for byte into the profiles folder of the run; `canary demo` and the demo of the interface call it before the run. The profile code is unchanged: it reads the copy as the saved profile of that chart of accounts, as it reads any saved profile. A copy was chosen over a new argument of the run because the pipeline needs no new surface and a later `canary run` on the demo folder with the same profiles folder finds the same file, so demo and run agree.
- **A file already in the profiles folder is kept.** The copy is made only when the folder has no file of that name: a profile there belongs to the person. No release has shipped the ledger, so no proposed leftover of an earlier demo exists in the field.
- **A person's own data is untouched.** The file name carries the fingerprint of the demo's chart of accounts; another chart finds no saved profile and gets a proposal, "proposed, not confirmed", as before (tested).
- **The gate's workaround is reverted.** `tests/cli/test_demo.py` no longer gives the second run another profiles folder; it asserts that the demo and the run both carry the run id of the committed manifest and compares the manifest and the two M08 files byte for byte.
- **Not done: the Windows program.** `packaging/canary.spec` bundles the workbooks of the demo and not the files beside the report, so the built program finds no shipped profile and still runs the demo on a proposal. The smoke test of `package` and `release` compares it with a source run that also proposes (another working folder, empty profiles), so that test is unaffected. Shipping the profile in the bundle needs a line in the spec and `--profiles` in the two workflows; both are outside this item's area and are left to the owner.
- **The skip test names what is skipped today.** A run on claim valuations alone skips M02, M05, M08, M09 and M10 (M08 since F1b, M10 since F2b; M07 runs on the recovery columns of the valuations). The test asserts that set and the first words of the two new reasons; it is stronger than before, not weaker.
- **The Turkish run id is read from its source.** `tests/ui/test_end_to_end.py` read a literal of 1.2.0; it now reads `reproducibility.run_id` of `tests/report/golden/baseline_tiny_tr.json` and also asserts that it differs from the English run id.
- **KF47 has a stated order.** The class counts are ordered by count descending, then class name (the unordered `group_by` with a stable sort on the count left equal counts in hash order). Every "largest gap" of the ledger section (the fact, the headline of the page, the per-class row, the list of the largest gaps) is ordered by absolute gap descending, then entity, class and month; the largest unmapped share by share descending, then entity. A hand table with two classes of equal count and three gaps of equal size gives the same text in both row orders; the test fails on the code before the change.

## Consequences
`canary demo`, the demo of the interface and `canary run` on the demo folder give the run id of the committed demo, `713ca5af937d4139`, when run from source. On the committed demo the counts of KF47 tie (RI 4, PREMIUM 4): the text now always reads PREMIUM first; whether the committed report changes is settled in stage 3. No estimate, measure or range changes. The tiny golden holds no ledger and does not move.
