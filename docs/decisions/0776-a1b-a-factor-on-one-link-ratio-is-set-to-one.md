# 0776 — A1b: a development factor that rests on one link ratio is set to 1.000 (R08)

## Context
`min_origins` (3) is checked on the triangle, not on each factor. The last link-ratio column of any triangle has exactly one origin, the one before it two. On the demo MOTOR_TPL the incurred factor 108-120 = 0.9300 rests on one origin and moves every cumulative factor; 1.000 adds 39.8 m (record 0775).

## Decisions
- **The rule.** A development factor that rests on fewer than `min_link_ratios` usable link ratios, but on at least one, is not taken from the average: it is 1.000 (neutral; the tail factor, not one origin, carries development beyond the data). It goes through the existing `selected` mechanism: `averages` keeps the average as the alternative, `overridden` is true, the new field `replaced` (bool per column) says that the rule did it, `n_ratios` (int per column) gives the usable, finite link ratios behind the average of each column (after exclusions, the diagonal window and exclude-high-low). `warnings` gets one string per replaced column. A column without any usable link ratio keeps today's behaviour (factor 1, its own warning). A factor selected in the register wins over the rule (the rule never touches an `overridden` column).
- **Where the default lives.** `chain_ladder(..., min_link_ratios=1)`: no rule, so every function-level benchmark of MT02, MT06 and the tier B methods stays as published (the existing benchmark tests pass unchanged). The module setting `ChainLadderSettings.min_origins_per_factor` (≥ 1) has the default **2**: only a factor on a single link ratio is replaced. It is passed through `chain_ladder_judged` and `chain_ladder_with_tail` to MT02, to MT06 (`mack(..., min_link_ratios=)`) and to MT07 (`inflation_adjusted_chain_ladder`, whose chain ladder is MT02 on the adjusted triangle; the nominal comparison chain follows it), so that the line pages, the paper-and-pencil factors, the cash flows and the ranges use the same factors.
- **Register.** The replaced factor is a `selected_factor` row with `who = rule`, `value` 1.000, `default` the average, and the reason in words ("rule: the column rests on 1 link ratio(s), fewer than 2; the average is not used and the factor is 1.000 (neutral)"). A user row for the same column replaces it and keeps its own who/when/why.
- **Mack.** The standard error is computed on the chain ladder with the replaced factor. A replaced column has one link ratio, so its variance parameter σ² was already extrapolated from the two columns before it (MT06, fewer than two ratios); that is unchanged. The process term σ²/f² uses f = 1.000 and the parameter term uses the column's own sums. Nothing in the Mack formulas changed. The test: on the RAA triangle the Mack reserve equals the chain ladder reserve with the rule, the standard error is finite.
- **Not changed on purpose.** MT12 (Munich) fits its own chain ladders, the bootstrap (MT11) refits on its pseudo-triangles with its own factors and then is rescaled to the selected reserve (0325, 0349), back testing (MT22) and the frequency-severity chains use the default; the rule reaches them through the selected reserve only. The MT14 tail fit reads the selected factors of the chain (as before), so a replaced last factor of 1.000 is a fit input: the fitted tails of the lines concerned can move (checked on the demo in record 0780).

## What the rule does to the benchmark triangles (function level, for information; the benchmark tests run with the default 1)
Last factor, reserve and Mack standard error without and with the rule (ten origins, one link ratio in the last column):
- RAA: 1.0092 → 1.0000; reserve 52,135 → 50,361 (−3.40 %); standard error 26,909 → 26,664.
- GenIns: 1.0177 → 1.0000; reserve 18,680,856 → 17,825,076 (−4.58 %); standard error 2,447,095 → 2,406,580.
- CLRD workers' compensation: 1.0102 → 1.0000; reserve 2,777,813 → 2,651,199 (−4.56 %); standard error 182,648 → 181,326.
On triangles with a factor above 1 in the last column the rule lowers the reserve; on the demo MOTOR_TPL (incurred 0.9300) it raises it.

## Consequences
- Tests: `tests/methods/test_a1b_thin_factors.py` (4 × 4 triangle with one and two ratios behind the last columns, setting 1 unchanged, a selected factor wins, exclusions lower the count, benchmarks unchanged by default, Mack on RAA, the register row). The module tests that work out numbers by hand from the plain averages (`test_reserving_wiring.py`, the own-model Monte Carlo file) run with `min_origins_per_factor=1`: their premise is the plain average (rewritten, not loosened); a new wiring test proves the default 2.
- Specs: MT02 (parameter and replaced column), M04 (setting and outputs) get new versions in stage 2.
