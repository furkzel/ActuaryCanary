# 0751 — A1a: named columns of the curve table, the tolerance of the negative-IBNR flag, run state in the appendix

## Context
R03: the curve table printed continuously compounded zero rates under the heading "Compounding: ANNUAL"; the discounting itself is right (an ANNUAL rate r is converted with ln(1 + r), so D(t) = (1 + r)^−t, CV10). R18: the NEGATIVE_IBNR diagnostic flagged an IBNR of −0.00. R19: see 0750.

## Decisions
- **Curve table (R03).** The columns are: tenor in years; the input rate with its type and compounding in the heading ("Input rate (spot rate, ANNUAL)"; for a par curve "par rate, annual coupons", for a forward curve "one-year forward rate, annually compounded"); the continuously compounded zero rate; the discount factor; the annually compounded forward rate from the previous tenor. The input rate is recomputed from the curve (`YieldCurve.input_rates()`: for SPOT the inverse of `zero_rate`, for PAR the par rate (1 − D(n)) / ΣD(m), for FORWARD the annual forward), so `build_curve` and every discount factor stay as they were; the points that PAR and FORWARD curves interpolate between the given years show the interpolated rate. The row "Compounding" of the cover list is now "Compounding of the input rate". The footnote states z = ln(1 + r) and D = exp(−z t) = (1 + r)^−t. `discount_curve.csv` keeps its columns (its `zero_rate` is the continuous rate and the footnote says so).
- **Tolerance of NEGATIVE_IBNR (R18).** An origin is flagged when ultimate − incurred < −max(0.005, 1e-9 × |ultimate|). 0.005 is half a cent, the amount below which the diagnostic text shows "0.00"; 1e-9 of the ultimate is the rounding noise of sums of amounts of 1e8 to 1e11 (the demo's −1.86e-9 on LIFE 2016 is far inside it). One function, `below_incurred`, serves `negative_ibnr` in `methods/diagnostics.py` and the property `ExpectedLossRatio.negative_ibnr` (MT05, which compared with 0 and treated NaN as 0; NaN is still not flagged). Hand test at the boundary: 0.0049 and 0.0051 below at 1000, 0.9 and 1.1 below at 1e9. No estimate moves, only the flag.
- **Appendix (R19).** `render_quality_section` is built before the analysis is at hand and `pipeline.py` is outside A1a, so the fragment carries one mark per module and `render_report` fills it from `module_runs` in the report model (state and reasons from `analysis.modules`). A fragment rendered alone keeps the marks as HTML comments.
- **Reserve-range labels (R19).** "Unpaid (paid triangle)" and "IBNR (incurred triangle)" in the table, the chart and its axis.
